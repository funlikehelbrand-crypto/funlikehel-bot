1. Czym jest SurfIQ

Definicja w jednym zdaniu

SurfIQ to system operacyjny dla szkół sportów wodnych — laczy rezerwacje, CRM, grafik instruktorów, prognozowanie pogody, finanse i agentów AI sprzedażowych w jeden system.

SurfIQ to NIE jest:

  • Kolejny kalendarz rezerwacji (Bookeo, Calendly)
  • Chatbot (Tidio, ManyChat)
  • CRM (HubSpot, Pipedrive)
  • Arkusz Excel z rezerwacjami

SurfIQ to JEST:

  • Jeden system który zastepuje 5-6 oddzielnych narzedzi
  • Zbudowany specjalnie dla szkol kite, wind, surf, eFoil, SUP, wing
  • Z agentami AI którzy odpowiadają klientom 24/7 na WhatsApp, Instagram, email
  • Przetestowany na prawdziwej szkole (FUN like HEL — Jastarnia + Hurghada)

"To nie jest kalendarz z chatbotem. To system operacyjny dla Twojej szkoły — jak jeden panel do zarządzania całym biznesem."

3. Agenci AI — Twój zespół sprzedażowy 24/7

Każdy plan SurfIQ zawiera agentów AI. To nie chatboty — to inteligentni asystenci, którzy znają Twój cennik, grafik, dostępność i odpowiadają klientom w ich języku.

Jak działają agenci?

  1. Klient pisze — na WhatsApp, Instagram, email, Messenger, SMS lub czat na stronie
  2. Agent AI czyta — rozumie jezyk, intencje, kontekst (cennik, grafik, dostępność)

  5. Tryb semi-auto: proste pytania (cena, godziny) — AI wysyla sam. Zlozone — draft do Ciebie

7. Bezpieczeństwo, logi i ochrona danych

Klienci pytają o bezpieczeństwo — oto co mówimy i co mamy.

Izolacja danych klientów

  • Row Level Security (RLS) — każda tabela w bazie ma politykę dostępu. Klient A nie widzi danych klienta B. Nawet jeśli ktoś zna ID rekordu — Supabase blokuje dostęp.
  • Organization ID — każdy rekord (rezerwacja, klient, wiadomość) jest przypisany do organizacji. Zapytania do bazy automatycznie filtrują po organization_id.
  • Role-based access — instruktor widzi tylko swoje lekcje. Recepcjonistka nie widzi finansów. Właściciel widzi wszystko.

Szyfrowanie i hosting

  • Szyfrowanie AES-256 — dane zaszyfrowane at rest (w bazie) i in transit (TLS 1.3)
  • Hosting w UE — serwer Supabase w Frankfurt (eu-central-1). Dane nie opuszczają Europy.
  • Backupy — codziennie automatyczne + tygodniowe pełne kopie
  • RODO / GDPR compliant — umowa DPA (Data Processing Agreement) w zestawie

Logi i monitoring

  • Audit log — każda akcja jest logowana: kto, co, kiedy, z jakiego IP
  • Analytics — widzimy jakie ekrany otwierają użytkownicy, jak długo, jakie funkcje używają
  • Session tracking — aktywne sesje, ostatnie logowanie, urządzenie
  • Error tracking — błędy łapane w czasie rzeczywistym z alertami

Ochrona przed kopiowaniem i scrapingiem

  • Security headers — X-Frame-Options: DENY (blokada iframe/clickjacking), X-Content-Type-Options, XSS Protection
  • Brak source maps w produkcji — kod JS jest zminifikowany, nie da się go łatwo odczytać
  • API wymaga tokenu — każde zapytanie do bazy wymaga JWT tokenu sesji. Bez logowania nie ma dostępu do danych.
  • Rate limiting — Supabase automatycznie limituje liczbę zapytań (ochrona przed brute-force i scrapingiem)
  • Token rotation — tokeny sesji odświeżają się automatycznie, wygasają po nieaktywności

Co widzimy jako operator platformy

  • Które moduły klient używa najczęściej
  • Ile AI rozmów przeprowadził
  • Czy system działa poprawnie (health checks)
  • Błędy i problemy techniczne
  • NIE widzimy treści rozmów z klientami ani danych finansowych — chyba że klient poprosi o wsparcie i udzieli dostępu
